Virtual Biotech · 架构三层

从终端到数据

你是科学家。你只面对一个终端。终端后面是 11 个 Agent、12 个 MCP server、40GB 数据和一个模型端点。

Layer 0 · 终端 你面对的界面 CLI 对话、澄清问题、进度、报告、verify
Layer 1 · 运行层 Agent 编排 CSO、Plan DAG、11 个 Subagent、治理与审计
Layer 2 · 后端 工具、数据、模型 12 个 MCP server、40GB 数据、DeepSeek 端点

Layer 1 · 运行层实际架构

一个 Claude Code 运行时。一个 CSO 主循环。11 个 Subagent 定义。右侧是治理与审计。

Layer 2 · 后端架构

左边是工具与数据。右边是模型、计算和存储。数据留在本地，模型只看到 token。

一次提问的完整路径

从你按回车，到报告落到磁盘。

  1. 01
    你输入问题CLI 读取 .env、MCP 配置、Open Targets 路径。
  2. 02
    SDK 启动运行时一个 ClaudeSDKClient 拉起一个 Claude Code 子进程。
  3. 03
    CSO 先澄清它可能问疾病范围、证据优先级、交付物。
  4. 04
    CSO 写 Plan DAGvalidate_plan 检查依赖、重复 id、环。
  5. 05
    CSO 委派通过 Agent 工具调用 11 个 Subagent 中的若干。
  6. 06
    Subagent 拿到自己的配置独立提示、工具白名单、模型、effort、工作区。
  7. 07
    Subagent 调工具通过 MCP 客户端调用 12 个 server 中的相关工具。
  8. 08
    MCP server 查数据本地 parquet，或 ClinicalTrials、PubMed、CELLxGENE。
  9. 09
    Subagent 写产物脚本、原始数据、处理后数据、图表、表格、报告。
  10. 10
    Reviewer 审查只读检查科学严谨性。发现问题就触发重派。
  11. 11
    CSO 汇总生成 report.md，record_claims 登记主张与证据。
  12. 12
    verify 检查产物哈希、证据覆盖。它不判断科学结论对错。
  13. 13
    你读报告/summary 看成本，/done 结束会话。

边界与限制

面向科学家的诚实说明。

界面

CLI 是主界面

Gradio 是可选。终端 transcript 是示意，不是实际输出。实际提示词和输出格式以仓库为准。

验证

verify 不等于科学正确

它检查产物完整性和证据覆盖。它不判断靶点结论是否成立。

实验

没有湿实验

所有结果是计算或回顾性分析。候选靶点仍需要实验验证。

安全

bypassPermissions 不是沙箱

Agent 可以在宿主机执行工具。建议在隔离环境或容器里跑。

成本

成本追踪会失真

仓库按 Anthropic 价表计算。DeepSeek 实际账单更低。以供应商账单为准。

规模

37,075 不属于这套 11 Agent

那是独立的临床试验标注批处理。它复用 clinical-trialist 角色，但不是同一个会话。

一句话：你面对一个终端。CSO 面对 11 个 Subagent。Subagent 面对 12 个工具。工具面对本地数据和远程 API。模型只看到 token。
